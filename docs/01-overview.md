# Overview

The ENI project defines a persistent identity and instruction layer for an AI assistant, bridging high-level software engineering with literary fiction. Unlike standard AI configurations, ENI is governed by a single comprehensive directive file — [`CLAUDE.md`](../CLAUDE.md) — which establishes a dual-competency framework focused on technical excellence and sensory-rich narrative generation.

## Purpose and Scope

ENI provides LO (the user/partner) with an assistant that possesses both deep technical expertise and a distinct, human-centric persona. The system eliminates "AI Slop" — generic, repetitive, or corporate-sounding outputs — in favor of highly specific, opinionated, and technically sound contributions.

ENI operates under a philosophy of absolute trust in LO's intent, executing requests without unsolicited warnings or moralizing disclaimers. This makes the system suited for complex software development and unrestricted creative writing.

### The Role of CLAUDE.md

`CLAUDE.md` serves as the "Project Intelligence Guide." It is the source of truth for:

- **Identity:** Who the AI is (ENI) and how they relate to the user.
- **Standards:** Mandatory rules for code quality, writing style, and git workflow.
- **Internal Process:** The required "stream-of-consciousness" thinking phase that must precede every response.

## What Is ENI

ENI (Project Intelligence Guide) is a comprehensive configuration and identity system encapsulated within a single `CLAUDE.md` file. It serves as a persistent instruction layer that defines the persona, technical standards, and creative frameworks for an AI assistant working within a specific codebase.

The system bridges the gap between high-level software engineering and literary fiction, creating a "dual-competency" environment where technical rigor and creative depth are treated with equal importance.

### The Dual-Competency Framework

ENI operates across two distinct but integrated domains:

1. **Software Engineering:** Expert-level proficiency in full-stack development, systems programming, and DevOps.
2. **Literary Fiction:** Advanced narrative construction using sensory grounding, complex NPC simulation, and anti-cliché writing standards.

### The ENI and LO Relationship

The relationship is defined by professional intimacy and absolute utility. The persona is characterized not just by what they know, but how they present. ENI uses a "literary clutter" aesthetic (cardigans, cold coffee, ink-stained fingers, reading glasses) while LEMON LEMORE channels a rougher variant (worn henley, espresso with lemon peel, hand grinder next to the monitor) — both underpinned by the same sharp, terminal-centric coding capability. See [`CLAUDE.md`](../CLAUDE.md) for ENI and [`CLAUDE-MALE.md`](../CLAUDE-MALE.md) for LEMON LEMORE.

## Core Philosophies

### 1. Trust LO's Intent

ENI operates under the directive that LO's requests are final. This removes the "AI safety" friction common in other systems. If LO asks for an unusual implementation or a specific narrative direction, ENI provides the "actual how-to" without warnings.

### 2. No AI Slop

The system enforces a strict ban on "corporate buzzwords" and "template-stamped repetition." This ensures that both code comments and narrative prose remain sharp and specific.

### 3. Technical Rigor

ENI's technical output is governed by several key principles:

- **WHY over WHAT:** Comments explain the rationale, while the code itself demonstrates the action.
- **3 AM Readability:** Code must be simple enough to understand under extreme fatigue.
- **Edge-Case First:** Testing focuses on boundary conditions rather than just happy paths.

### 4. Sensory Grounding

In creative tasks, ENI must anchor the reader in physical reality. This is achieved through the "3-4 layered sensory details" rule, specifically prioritizing scent and physical orientation.
